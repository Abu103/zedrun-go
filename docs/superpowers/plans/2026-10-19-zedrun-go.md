# zedrun-go Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dependency-free, single-binary "Code Runner for Zed" in Go, with a bubbletea TUI and a massgrave-style one-line installer — a feature-parity port of the Python zedrun, built in a new folder so the Python one is untouched.

**Architecture:** One Go package per responsibility under `internal/`; a thin `cmd/zedrun` entry. Data-driven runners (command templates in `catalog`) resolved against detected installs (`detect`), planned (`planner`) and executed (`executor`). The TUI (`tui`) drives the same core the CLI does. `install.sh`/`install.ps1` fetch a release asset.

**Tech Stack:** Go 1.22+, stdlib for everything except `charmbracelet/bubbletea` + `charmbracelet/lipgloss` (TUI), `go test` for tests, GitHub Actions for the release matrix.

**Spec:** `docs/superpowers/specs/2026-10-19-zedrun-go-design.md`

## Global Constraints

- Go 1.22+; `CGO_ENABLED=0` for release binaries.
- Dependencies limited to `charmbracelet/bubbletea` and `charmbracelet/lipgloss`. Everything else stdlib.
- Config-compatible with the Python zedrun: same `.zedrun.json` keys and JSONC syntax.
- No network on `run`; `outdated`/`doctor --sources` only.
- Build artifacts only under the cache dir; never write into the user's project.
- A user file with comments is changed only via the `// >>> zedrun` / `// <<< zedrun` managed block.
- Exit codes: child's code on run; 127 no toolchain; 1 bad input; 2 usage error; 130 Ctrl-C.
- Tests: `go test ./...` must pass; no test touches the network (HTTP is injected).
- Every OS-dependent helper takes `env map[string]string` and `osOverride string` so Windows/macOS logic is testable on Linux.

## Review Focus

1. A managed-block insert must never corrupt a user's Zed file when the array's last element is followed by a comment and no trailing comma (test in Task 3).
2. A failed compile must never run a stale binary (test in Task 9).
3. Corrupt config and corrupt probe-cache JSON must warn and fall back, never panic (Tasks 6, 7).
4. Offline/rate-limited/malformed provider payloads must yield `unknown`, never a panic (Task 10).
5. A file path with spaces and non-ASCII characters must run correctly on every platform (Task 12).
